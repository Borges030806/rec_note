# 分层实验

流量是有限的，而且分桶也是有限的，多层多个A/B测试会导致流量不够用，应该遵循分层实验
![[Pasted image 20260603203905.png]]

一个用户不能同时受到两个召回实验的影响，但是可以同时受到一个召回实验和一个精排实验的影响
下图例子中，一个召回实验和一个精排实验各自作用在n/10个用户上，那么有n/100的用户同时受到两个实验的影响（不同层正交）

![[Pasted image 20260603204054.png]]![[Pasted image 20260603204311.png]]
![[Pasted image 20260603204742.png]]
关于这里的正交，理解如下：因为不同层的哈希分桶是独立的，所以理论上召回层做的实验也会均匀散步在粗排层的不同桶中，也就意味着粗排层的实验组和对照组受到召回层的影响应该也是差不多的，所以依旧是可比的

# Holdout机制
![[Pasted image 20260603205920.png]]
![[Pasted image 20260603210217.png]]

holdout桶是干净的，任何新的实验都不能作用到holdout用户，用剩余90%用户做实验，且推荐系统的四层是正交的，所以召回层可以对这90%的用户全部做实验，粗排层也可以
![[Pasted image 20260603210227.png]]
计算90%用户的实验桶和10%holdout桶的各种指标的diff，作为整个推荐部门对业务指标的贡献

![[Pasted image 20260603210555.png]]


# 实验推全和反转实验

所有实验都是从小流量开始，如果业务指标的diff显著正向，则可以推全实验，此时把原层的实验组关掉（此时可以把桶空出来给其他实验使用），推全的时候会新开一层，此时新策略会影响全部百分之九十的用户，如果小流量取的10%用户，那么理论上推全后带来的diff会是小流量的九倍
![[Pasted image 20260603210951.png]]


## 反转实验
![[Pasted image 20260603211219.png]]
推全的新层也是和另外四层正交的

![[Pasted image 20260603211316.png]]

一个考核周期结束后，会清除holdout桶（推全的新策略会作用到holdout用户上），但不会影响反转桶。当反转实验完成时，关闭反转实验，新策略会应用到反转桶的用户上，此时达到真正的推全

每推全一个策略，都会新建一个推全层，覆盖90%的用户
